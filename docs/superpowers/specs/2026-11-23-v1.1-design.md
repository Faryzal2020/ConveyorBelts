# ConveyorBelts v1.1 — Design (feedback from first play test)

Status: **approved 2026-11-23.** Not built yet.
Date: 2026-11-23 · Builds on: `PLAN.md` (v1 spec) and the code on `main` (`6ba4fee`).

Legend: **[You]** = your requirement or answer. **[Proposal]** = my call, open to correction.
Where this document and `PLAN.md` disagree, this document wins; `PLAN.md` gets updated to match when v1.1 lands.

---

## 1. Intent

You played v1 and found six things that feel wrong or clumsy. The biggest is the Pusher: it should be a **bridge
between any two item holders**, not a belt end that grabs and holds items. The rest is about fast,
uncluttered control: flip the L with Q/E, a filter you can set by category or search in a few clicks, short
UI text, and conduits that can run under belts and ports.

### Goals
1. Q/E flips the L direction while placing a belt path **[You]**.
2. Pusher redesign: no holding; pulls from whatever is behind it, pushes into whatever is in front, filter-gated **[You]**.
3. New filter tab for every port with a filter (Input Port, Pusher): category tree, strong search with "Allow all",
   and a list of everything currently allowed **[You]**.
4. Pusher tab shows "Pulling from" / "Pushing to", "None" when empty **[You]**.
5. Short, non-repeating UI text everywhere; "Upgrade" / "Downgrade" buttons whose icon shows the target tier **[You]**.
6. Power conduits can share a cell with belts and ports **[You]**.

### Non-goals
- Underground belts (separate, later).
- Balancing numbers (speeds, costs, power) — still placeholders.
- Explaining behaviour in tooltips: "if the UI design is clear and the pull/push behaviour is uniform, the player needs
  no text explanation" **[You]**.

### Anti-goals
- A Pusher that moves anything when its filter is untouched (new pushers must do nothing until configured).
- A Pusher that pulls a **live pawn** out of anything (cryptosleep caskets, etc.) **[You]**.
- A Pusher that drops items on plain ground **[You]**.
- Item loss or duplication during a pull/push (inherited from v1).
- UI text that repeats what the icon or graphic already shows **[You]**.

## 2. Placement: Q/E flips the L **[You + Proposal]**

- **Before the first click:** Q/E rotate the single-tile direction, as today (vanilla rotation keys,
  `Designator_RotateLeft` / `Designator_RotateRight`).
- **After the first click (start pending):** either key toggles the L between "across first, then up/down"
  (X-first) and "up/down first, then across" (Z-first). The ghost preview updates immediately. On a straight line the
  toggle changes nothing visible.
- The chosen order is remembered for the next path in the same placement session **[Proposal]** (resets to X-first
  when the designator is deselected).
- Shift no longer changes the L **[Proposal]**.
- Example **[You]**: click (0,0), move the mouse up-right → preview "right first, then up"; press Q or E →
  "up first, then right".

## 3. Pusher redesign **[You]**

### 3.1 Behaviour
- **No internal holding.** The pusher never takes an item it can't place. It checks both sides first and only then
  moves the item in one step.
- **Pull side = the cell behind it** (opposite its facing). **Push side = the cell in front.**
- **A move happens only when all of these are true:** the pusher is powered; an item on the pull side is allowed by
  its filter; the push side can take at least part of it right now.
- **Filter default: nothing allowed** **[You]** — a new pusher does nothing until configured.
- **Never pulls live pawns** **[You]**. Corpses are ordinary items and follow the filter **[You]**.
- **Never pushes onto plain ground** **[You]**. Without a valid push target the pusher waits.
- **Forbidden items are pulled too** — forbidding is about pawns; a pusher whose filter matches is expected to pull
  them **[You]**. A toggle **"Pull from forbidden"** in the Pusher tab turns this off; default **on** **[You + Proposal:
  default]**. Moved items keep their forbidden state **[Proposal]**.
- **Items a pawn has reserved** (a pawn is on its way to haul or use it) are skipped, so the pusher never breaks a
  pawn's job **[Proposal]**.
- Not a belt sink any more: a belt pointing into a pusher simply stops at its end; the pusher pulls from there.
- **Rate [Proposal, placeholder]:** one move every 60 ticks (1 s at 1×); a move transfers as many as the target can take,
  at most one full stack of that item (and at most the belt's max stack when pushing onto a belt).

### 3.2 What counts as a pull source (approach A, generic first) **[You: approach A]**
Checked in this order on the cell behind; the first source with an item the filter allows *and* the target can take
wins **[Proposal]**:
1. **Belt:** a belt on that cell pointing toward the pusher → its front item, only once it has reached the tile's end
   (keeps belt order).
2. **Items lying on the cell:** spawned haulable items on that cell — shelves, stockpile cells and plain floor alike.
3. **A building's container:** any building on that cell that holds things through the standard RimWorld
   `IThingHolder` container (transport pods, sarcophagi/graves, autonomous machines that hold their ingredients or
   products, modded machines). Live pawns skipped. Note: plain work tables and shelves are not containers in 1.7;
   their products and contents lie on cells and are covered by rule 2.
4. **Product adapters** for machines that keep their product as a count, not as a held item. v1.1: **fermenting barrel →
   beer** (vanilla `TakeOutBeer`, only when fermented). More can be added later.

### 3.3 What counts as a push target (generic first)
Checked in this order on the cell in front **[Proposal]**:
1. **Belt** pointing away from the pusher (or sideways, as long as it doesn't point straight into the pusher) → insert
   like the Input Port does.
2. **Machine adapters** kept from v1: fuel (`CompRefuelable`), wort into a fermenting barrel, construction frames.
3. **Any haul destination** with room: shelves, hoppers, stockpile cells, graves (corpses), and storage mods that use
   vanilla's storage interfaces. "Room" = the same stack/cell capacity rules vanilla hauling uses.
- **Not a push target in v1.1:** generic containers (transport pods, caskets, sarcophagi, modded machines' insides)
  **[You]**. Special machines such as Rimatomics reactors (fuel rods) get their own compatibility adapter later, not a
  generic insert **[You]**.
- Removed from v1: reject modes, eject side, "throw to the side", the one-item buffer.

### 3.4 Pusher tab
```
Pulling from: Shelf
Pushing to:   Belt
[✓] Pull from forbidden
──────────────────────────────
<filter tab, §4>
```
- "None" when a side has no valid source/target **[You]**. No other status text **[You]**.
- Each line names the building (or "Belt" / the item's cell) the pusher **recognises** on that side, whether or not
  anything can move right now — so the player can see the pusher understands the setup **[Proposal]**.
- Copy / paste copies the filter and the forbidden toggle **[Proposal]**.

### 3.5 Old saves
- A v1 pusher holding a buffered item: on load the item is dropped on the pusher's cell (no loss) **[Proposal]**.
- v1 reject-mode / eject-side values are ignored, and v1 pushers come back with an empty filter like new ones, so they
  do nothing until you set them **[Proposal]** (v1 saves are play-test saves).

## 4. Filter tab (Input Port and Pusher) **[You — mockup agreed 2026-11-23]**

```
<port-specific lines: Input Port = haul priority; Pusher = Pulling from / Pushing to>
──────────────────────────────────────────────────
Items                                      [All] [None]
[ search…                                          ]
┌ Categories ──────────────┐ ┌ Allowed (14) ──────────┐
│ ▾ ◩ Resources            │ │ Component            ✕ │
│    ▸ ■ Manufactured      │ │ Advanced component   ✕ │
│    ▸ □ Raw resources     │ │ Medicine             ✕ │
│ ▸ □ Foods                │ │ AMC 20mm shell       ✕ │
│ ▾ ◩ Weapons              │ │ …                      │
│      ■ AMC ammo          │ │                        │
│ ▸ □ Corpses              │ │                        │
└──────────────────────────┘ └────────────────────────┘

While searching ("ste"):
┌ 4 results   [Allow all] ┐ ┌ Allowed (15) ──────────┐
│ ■ Steel          Raw    │ │ Steel                ✕ │
│ □ Plasteel       Raw    │ │ …                      │
│ □ Stone blocks   category│ │                        │
│ □ Steel sword    Melee  │ │                        │
└──────────────────────────┘ └────────────────────────┘
```
- **Left pane, browsing:** vanilla thing-category tree with tri-state boxes (all / some / none allowed). Expand/collapse.
  No hit-point/quality sliders, no "special filters" **[You: simpler than vanilla]**.
- **Left pane, searching:** flat list of matching **items and categories** (label contains the text, case-insensitive),
  each with a checkbox and a small tag (its category, or "category"). **"Allow all"** allows every shown result
  **[You]**; when every shown result is already allowed it reads "Disallow all" **[Proposal]**.
- **Right pane:** every allowed item from all ticked categories and single picks, sorted by label, each with ✕ to
  disallow it **[You]**.
- **All / None:** the whole filter.
- Which items appear: everything haulable, corpses included; minified buildings follow the vanilla category **[Proposal]**.
- Input Port keeps editing its vanilla storage settings underneath (hauling keeps working); the Pusher's filter is its
  own saved filter.

## 5. UI text pass **[You + Proposal]**

Rule **[You]**: short labels; no text that repeats what the icon, graphic or another line already says; vague is fine.
Tooltips only where a label alone is ambiguous **[Proposal]**.

| Where | v1 | v1.1 **[Proposal]** |
|---|---|---|
| Tier gizmo | "Upgrade to fast" / "Downgrade to basic" + long description | "Upgrade" / "Downgrade"; icon = the target tier's belt picture **[You]**; no description |
| Belt-being-upgraded deconstruct reason | "Replacement planned: … Cancel that plan to deconstruct this belt." | "Upgrade planned" |
| Motor status | "Driving 6 tiles, 50 W" / "Line already driven" / "No belt in front" | "Driving 6 tiles, 50 W" / "Standby" / "Idle" |
| Our own "no power" lines | "Not feeding belts: no power." etc. | removed (vanilla already shows no power) |
| Pusher tab | "Facing: …", "Accepts now: …", reject modes | "Pulling from: …" / "Pushing to: …" / "None" **[You]** |
| Port-tab gizmos | "Configure items", "Output settings", "Pusher settings" + descriptions | one label, e.g. "Settings", no description |
| Output Port tab | "Hold (belt backs up)" / "Spill (drop nearby)" + descriptions | "Hold" / "Spill" |
| Empty values | mixed ("nothing", "Nothing yet: search below…") | "None" |
| Select line | label + long description | "Select line" only |

The builder applies the rule to every remaining key in `CB_Keys.xml` the same way.

## 6. Conduits **[You]**

- Power conduits (every vanilla conduit kind: normal, waterproof, hidden **[Proposal]**) may share a cell with belts and
  ports, whichever is built first.
- Everything else stays blocked on belt cells (surface rule from 2026-11-21).
- Implementation: allow `building.isPowerConduit` in `BeltCellRules` (both directions); confirm ports accept a conduit
  underneath and vice versa.

## 7. Approaches considered (Pusher sources/targets)

| | Approach | Trade-off |
|---|---|---|
| **A (chosen)** | Generic first: belt end, items on the cell, any building's standard container, any haul destination; tiny adapters only for count-based products (barrel beer) and the v1 machine inputs. | "Take from anything, push to anything" holds for vanilla and most mods with no extra code. An unusual modded container may react oddly when something is removed; the filter is the guard, and testing will reveal cases **[You: accepted]**. |
| B | Adapter per building type, both sides. | Predictable, but every new machine/storage mod needs code; breaks the "anything" rule. |
| C (dropped) | Pusher simulates a pawn doing vanilla haul jobs. | Heavy, slow, fights the job system. |

## 8. Testing
- Unit tests for any new pure logic (e.g. the L toggle in `BeltPath`, move-amount calculation).
- In game (RimTestHarness): shelf → pusher → belt; belt → pusher → shelf; fermenting barrel (fermented) → pusher →
  shelf with a "Beer" filter; corpse on a shelf → pusher → grave; filter untouched → nothing moves; cryptosleep casket
  with a colonist → nothing moves; no target / plain ground in front → waits; unpowered → nothing moves; old v1 save
  with a buffered pusher → item dropped, no errors; conduit under belt / port both orders; filter tab operations driven
  through the same methods the widgets call.
- Manual window checks for you: Q/E flip in the preview, filter tab clicks and scrolling, gizmo icons.
- Mod compatibility: tested by you as you play **[You]**.
